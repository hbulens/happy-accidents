# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Commands

Package manager: **bun**.

- `bun dev` — Vite dev server on port 3000 (TanStack Start, client-rendered pages with an SSR'd shell)
- `bun run build` — production build (Nitro preset `vercel`)
- `bun run typecheck` — `tsc --noEmit`
- `bun test` — vitest (tests live in `test/`)
- `bun run demo:images` — paints the demo lesson's pictures into `public/demo` (needs `REPLICATE_API_TOKEN` in `.env` or `.env.local`; reuses an existing `final.webp`, pass `--repaint` to redo it)
- `bun run lint` — eslint

`src/routeTree.gen.ts` is generated by the router plugin; do not edit or commit it.

## Architecture

- **Routes** (`src/routes/`) are thin. API handlers live in `src/routes/api/*` (TanStack constraint) and delegate to `src/features/lessons/server/*`.
- **Feature code** is under `src/features/lessons/`. Server modules import `@anthropic-ai/sdk`; never import them from components.
- **Schema first.** `src/features/lessons/schema.ts` is the single contract: it drives the structured-output format on the server and the types on the client. Keep it within the structured-outputs JSON schema subset: no numeric min/max, no `.optional()` (use `.nullable()`), no tuples.
- **Prompts** in `src/features/lessons/prompts.ts` encode the wet-on-wet method. Changing technique text there changes what every lesson teaches.
- **Pictures** come from Replicate (`src/lib/replicate.ts`, `server/images.ts`): Flux 2 Pro paints the finished picture from `lesson.paintingPrompt`; Flux Kontext Pro then walks backwards, removing each step's `paintsIn` from the next step's picture (an edit model removes reliably but cannot 'show an earlier stage'), so step pictures arrive last step first. Results stream as SSE `image` events and are cached in IndexedDB (`utils/image-db.ts`, `stores/image-store.ts`). Demo lesson pictures are static files in `public/demo` produced by `bun run demo:images`.
- **Generation runs in a store** (`stores/generation-store.ts`), not in a component, so it survives navigating from the creator to the lesson page while step pictures are still arriving.
- **Voice**: `hooks/useVoiceCommands.ts` (continuous Web Speech recognition, restarts on end, holds while TTS speaks) and `hooks/useSpeech.ts` (speechSynthesis). The parser in `utils/commands.ts` is pure and unit tested; add new commands there with a test.
- **State**: zustand with `persist` under key `happy-accidents/v2`. Bump the key if the lesson shape changes incompatibly.
- **Secrets**: `vite.config.ts` copies `ANTHROPIC_API_KEY`, `REPLICATE_API_TOKEN` and the `HAPPY_ACCIDENTS_*` settings from `.env` / `.env.local` into `process.env` at startup. Restart `bun dev` after editing those files. Replicate accounts under $5 credit are throttled to a burst of 1 prediction; the client retries on 429.

## Claude API usage

Model `claude-opus-5`, adaptive thinking, `output_config.format` via `zodOutputFormat`, `messages.stream` with `finalMessage()`. Handle `stop_reason === 'refusal'` and `'max_tokens'` explicitly (see `server/generate-lesson.ts`). Use typed SDK error classes, not string matching.
